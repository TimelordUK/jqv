# 6. Choosing: `if … then … else … end`

`select` (lesson 3) decides which records stay. `if` keeps every one and decides what each
becomes. It runs once for each value that reaches it, and inside it `.` is that value.

Input: [people.json](../testdata/people.json)

## Start from the names

```jq -c
[.[].people[].name]
```

```json output
["Ann","Bob","Cat","Dan"]
```

## Two ways for each name

A name that starts with A or C is labelled; any other is lower-cased. The test is one
expression, here two tests joined with `or`, and `"\(.)"` puts the name into a string:

```jq -c
[.[].people[].name | if startswith("A") or startswith("C") then "\(.) (A or C)" else ascii_downcase end]
```

```json output
["Ann (A or C)","bob","Cat (A or C)","dan"]
```

`test` with a regular expression says the same in one go:

```jq -c
[.[].people[].name | if test("^[AC]") then "\(.) (A or C)" else ascii_downcase end]
```

```json output
["Ann (A or C)","bob","Cat (A or C)","dan"]
```

## More than two ways: `elif`

Start from the person rather than the name, so the test can look at `.age` while each branch
picks `.name`. A branch can be a whole pipeline:

```jq -c
[.[].people[] | if .age > 30 then .name | ascii_upcase elif .age > 26 then .name else .name | ascii_downcase end]
```

```json output
["Ann","bob","CAT","DAN"]
```

The branches are tried in order, and the first test that holds wins: Cat (41) is over 30, so
the `elif` is never asked.

## Branches that build

A branch can give anything, an object included. This labels each person rather than
changing them:

```jq -c
[.[].people[] | if .age > 30 then {name, band: "over 30"} elif .age > 26 then {name, band: "late 20s"} else {name, band: "young"} end]
```

```json output
[{"name":"Ann","band":"late 20s"},{"name":"Bob","band":"young"},{"name":"Cat","band":"over 30"},{"name":"Dan","band":"over 30"}]
```

## No `else`

Since jq 1.7 `else` can be left out, and then the value goes through as it was:

```jq -c
[.[].people[].name | if startswith("A") then ascii_upcase end]
```

```json output
["ANN","Bob","Cat","Dan"]
```

## What counts as true

Only `false` and `null` are false. `0`, `""` and `[]` are all true, unlike in many languages:

```jq -nc
[0, "", [], null, false] | map(if . then "true" else "false" end)
```

```json output
["true","true","true","false","false"]
```

So a missing field (`null`) takes the `else`:

```jq -c
[.[].people[] | if .role then .role else "no role" end]
```

```json output
["no role","no role","no role","no role"]
```

`//` says that more briefly: the left side unless it's `false` or `null`, then the right:

```jq -c
[.[].people[] | .role // "no role"]
```

```json output
["no role","no role","no role","no role"]
```

## `if` and `select`

`if … then . else empty end` keeps a value or gives nothing, which is `select` written out:

```jq -c
[.[].people[] | if .age > 30 then . else empty end] == [.[].people[] | select(.age > 30)]
```

```json output
true
```

## A test with several answers

The test is a generator like any other filter (lesson 5): when it gives several answers, the
`if` runs once for each, so one value can come out several times:

```jq -nc
[if (true, false) then "yes" else "no" end]
```

```json output
["yes","no"]
```

## In jqv

A long `if` is hard to read on one line. `:fmt` (or `F8` on the line being typed) lays it out:
an `if` with a pipeline in a branch, an `elif`, or more than 60 characters opens up, each
branch indented under `then`, `elif` and `else`. A short one such as `if . then 1 else 2 end`
stays on its line. The `elif` line above comes out as

```text
[
    .[].people[]
    | if .age > 30 then
        .name
        | ascii_upcase
    elif .age > 26 then
        .name
    else
        .name
        | ascii_downcase
    end
]
```

`F5` with the cursor inside a branch runs the line up to there, to see what reaches it.
